# Reference R3 — 錯誤代碼速查

本文件彙整歐買尬常見錯誤代碼與排除建議。實際代碼請以歐買尬官方文件為準。本表僅作為故障排除的快速對照用途。

## 錯誤代碼分類

歐買尬錯誤代碼多為 8 位數，前兩位通常表示分類：

- `101xxxxx` — 系統層級錯誤（參數、簽章、商家狀態）
- `102xxxxx` — 交易層級錯誤（卡片拒絕、餘額不足、訂單異常）
- `103xxxxx` — 退款相關錯誤
- `104xxxxx` — 查詢相關錯誤

## 常見錯誤代碼

### 參數與簽章錯誤（101xxxxx）

| 代碼 | 說明 | 可能原因 | 排除建議 |
|---|---|---|---|
| 10100050 | CheckMacValue Error | MAC 不一致 | 檢查 HashKey、HashIV、欄位排序、URL encoding |
| 10100051 | 必填欄位缺漏 | payload 欄位不完整 | 對照 `references/api-endpoints.md` 補齊 |
| 10100052 | 金額格式錯誤 | 送出非整數金額 | 將金額轉為整數字串 |
| 10100053 | MerchantID 格式錯誤 | 非純數字或長度錯誤 | 確認後台設定 |
| 10100060 | MerchantTradeNo 重複 | 訂單號曾被使用 | 產生新的唯一訂單號 |
| 10100070 | MerchantTradeDate 格式錯誤 | 格式非 `yyyy/MM/dd HH:mm:ss` | 校正 datetime format |

### 交易錯誤（102xxxxx）

| 代碼 | 說明 | 可能原因 | 排除建議 |
|---|---|---|---|
| 10200047 | 查無此筆交易 | 訂單不存在或尚未同步 | 等待同步或確認訂單號 |
| 10200095 | 付款失敗 | 銀行拒絕 / 餘額不足 | 請消費者更換卡片或聯絡發卡行 |
| 10200027 | 金額超過單筆限額 | 超過商家可單筆收款上限 | 分拆訂單或向歐買尬申請調整 |
| 10200050 | 卡片被拒絕 | 卡片被銀行拒絕授權 | 請消費者聯絡發卡行 |
| 10200051 | 3DS 驗證失敗 | 消費者未完成 3DS | 提醒消費者完成驗證 |
| 10200072 | 卡片已過期 | 卡片過期 | 請消費者更換卡片 |
| 10200073 | CVV 錯誤 | 輸入錯誤 | 請消費者重新輸入 |
| 10200100 | 商家帳號被停用 | 違規或未完成認證 | 聯繫歐買尬客服 |

### 退款錯誤（103xxxxx）

| 代碼 | 說明 | 可能原因 | 排除建議 |
|---|---|---|---|
| 10300001 | 該訂單狀態不允許退款 | 訂單未付款或已全退 | 確認訂單狀態 |
| 10300002 | 退款金額超過可退額度 | 請求金額大於剩餘可退 | 減少退款金額 |
| 10300003 | 該訂單已超過可退期間 | 超過歐買尬規定的退款期限 | 聯繫歐買尬客服或透過其他方式處理 |
| 10300010 | 發卡行拒絕退款 | 銀行系統問題 | 稍後重試或聯繫歐買尬 |
| 10300020 | 重複退款請求 | 相同請求於短時間內多次送出 | 實作冪等性，避免重試 |

### 查詢錯誤（104xxxxx）

| 代碼 | 說明 | 排除建議 |
|---|---|---|
| 10400001 | TimeStamp 已過期 | 確認時間同步，送出當前秒數 |
| 10400002 | 查詢期間超過限制 | 縮短查詢區間 |
| 10400003 | PlatformID 錯誤 | 非平台商應留空 |

## 網路層錯誤

除歐買尬回傳之錯誤外，整合過程也可能遭遇下列網路層錯誤：

| 錯誤類型 | 說明 | 排除建議 |
|---|---|---|
| `ConnectionError` | 無法連線至 API host | 檢查防火牆、DNS、host 設定 |
| `TimeoutError` | 連線逾時 | 增加 timeout 值，或確認網路品質 |
| `SSLError` | TLS 握手失敗 | 更新 CA 憑證，確認系統時間正確 |
| `TooManyRedirects` | 連續 redirect | 確認 host URL 是否正確 |
| `HTTP 502/503/504` | 後端服務暫時不可用 | 重試（含退避），或聯繫歐買尬 |

## Webhook 層錯誤

接收 webhook 時可能遭遇的錯誤：

| 情境 | 處理方式 |
|---|---|
| CheckMacValue 驗證失敗 | 回傳 400，寫入 `callback_logs` 但不處理 |
| 訂單號不存在 | 回傳 200（避免歐買尬重試），記錄為 orphan callback |
| 資料庫寫入失敗 | 回傳 500，讓歐買尬重試 |
| payload 格式錯誤 | 回傳 400，記錄原始內容 |

## 錯誤處理原則

1. **使用者可見錯誤**：轉換為使用者可理解的中文訊息（例：「您的信用卡被發卡行拒絕，請聯絡發卡銀行或更換卡片」）
2. **系統層錯誤**：不得暴露於使用者介面，僅記錄於 log 與監控系統
3. **可重試錯誤**：採用指數退避（exponential backoff）重試，避免對歐買尬造成壓力
4. **不可重試錯誤**：立即標記失敗並記錄於 audit log

## 錯誤訊息轉換建議

```python
ERROR_MESSAGE_MAP = {
    "10100050": "系統驗證失敗，請稍後再試。若問題持續請聯絡客服。",
    "10200047": "查無此筆交易，請確認訂單號。",
    "10200050": "您的信用卡被發卡行拒絕，請聯絡發卡銀行或更換卡片。",
    "10200051": "3DS 驗證未完成，請重新付款並完成驗證。",
    "10200072": "您的信用卡已過期，請更換卡片。",
    "10200073": "信用卡 CVV 驗證錯誤，請重新輸入。",
    "10300001": "該訂單目前狀態不允許退款，請確認訂單狀態。",
    "10300002": "退款金額超過可退額度。",
    "10300003": "該訂單已超過可退款期間，請聯絡客服協助處理。",
}


def user_friendly_message(code: str, default: str = "交易處理失敗，請稍後再試") -> str:
    return ERROR_MESSAGE_MAP.get(code, default)
```

使用者介面應優先呼叫 `user_friendly_message()` 取得訊息，不得直接顯示歐買尬原始錯誤訊息。

## 追查與回報

若遭遇未知的錯誤代碼：

1. 於測試儀表板記錄完整 payload 與回應內容
2. 遮蔽敏感資訊（金鑰、訂單號之客戶識別）後建立 GitHub Issue
3. 若為業務阻擋性問題，同步聯繫歐買尬客服並提供歐買尬交易號（`TradeNo`）

本 Skill 之錯誤代碼表會持續依社群回報更新，歡迎透過 Pull Request 補齊未收錄的代碼。
